# Aggregation as Admission to Reserve Markets

Code, processed inputs and results of the paper

> L. Giannuzzo, D. S. Schiera, F. D. Minuto, A. Lanzini, *Aggregation as Admission to Reserve Markets: Value and Stable Revenue Sharing of Pooled Heterogeneous Battery Storage Under a Minimum Bid Size*, manuscript submitted for publication.

The paper schedules twenty batteries of three sizes (8 × 0.5 MW / 4 h, 8 × 1.0 MW / 2 h, 4 × 2.5 MW / 1 h) on the Italian day-ahead market and on six directional reserve products (FCR, aFRR and mFRR, upward and downward) for 2023 and 2024, with a minimum bid of 1 MW applied either to the offer of each unit (standalone) or to the combined offer of the portfolio (aggregated). It then values the cooperative game of the twenty units exactly, on all class compositions and every day of both years, and tests four allocation rules, the Shapley value and the nucleolus against the core.

## Repository structure

```
src/
  scheduling_milp.py   daily MILP of a coalition of units under the minimum bid (reference and preliminary formulations, variants)
  experiments.py       scenarios, exact cooperative game, value of admission by duration, compositions, bridge
  postprocess.py       Shapley value, nucleolus, core, largest excess of each rule, fixed cost, Monte Carlo replay
  core_width.py        width of the core of every composition for one small unit (Fig. 5)
  collect_results.py   merges the timestamped summaries into results/scenarios.csv and results/durations.csv
  export_inputs.py     hourly model inputs to data/processed/
  market_data.py       GME day-ahead prices and MSD-based reserve catalog
  market_products.py   reserve product definitions
data/
  raw/                 GME downloads, to be added by the user (see data/README.md)
  processed/           hourly inputs of the reference runs, 2023 and 2024
results/               annual results used in the paper (see below)
figures/               scripts that rebuild Figs. 2 to 6 and Figs. S1 and S2 from results/ and data/processed/
tables/                script that rebuilds the values of Tables 4 to 10 from results/
```

Fig. 1 is a methodological diagram and is not generated by code.

## Installation

Python 3.12 (the paper used 3.12.2):

```bash
pip install -r requirements.txt
```

The results of the paper were obtained with Gurobi 13.0.2 under an academic license, through PuLP 2.9.0. When Gurobi is not available, the code uses HiGHS (`pip install highspy`) or the CBC solver bundled with PuLP, which reach the same optima within the solver tolerance but are slower. The number of solver threads per process is set with the environment variable `MILP_THREADS`.

## Rerunning the experiments

Download the GME files into `data/raw/` (see `data/README.md`), then run from `src/`. Each command writes timestamped summaries to `--outdir`, and `collect_results.py` merges them.

```bash
cd src
export MILP_THREADS=1
PUN="../data/raw/20230101_20231231_PUN.xlsx ../data/raw/20240101_20241231_PUN.xlsx"
MSD="../data/raw/EsitiMSD_PrezziExAnte_*_Nord.xlsx"
OUT=../results/new

# 0. quick check, one week of 2023 (minutes)
python experiments.py --scenarios ref --years 2023 --days 7 --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT

# 1. reference, exact game and value of admission by duration (about 45 worker-hours per year)
python experiments.py --scenarios ref --years 2023 --game --workers 4 --durations 1 2 4 --dump --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT
python experiments.py --scenarios ref --years 2024 --game --workers 4 --durations 1 2 4 --dump --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT

# 2. variants of Table 9 (several hours)
python experiments.py --scenarios minbid05 minbid025 gran1 fcrsym phi047 fcr25 fcr10 nofcr afrr05 afrr15 energyonly alpha05 alpha025 \
    --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT
python experiments.py --scenarios deg150 deg25 hist hist30 histnouvam fcrdepth persist1 persist7 --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT
python experiments.py --durations-scenarios ref afrr05 afrr15 energyonly hist --durations 1 2 4 --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT

# 3. coalitions under the price-responsive FCR and under whole-megawatt offers
python experiments.py --comps "8,0,0;0,8,0;0,0,4;8,8,0;8,0,4;0,8,4" --comps-scenario fcrdepth --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT
python experiments.py --comps "8,8,3;8,7,4;7,8,4" --comps-scenario gran1 --years 2023 --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT

# 4. bridge from the preliminary to the reference formulation (Fig. 6, Table 10)
python experiments.py --bridge --pun-xlsx $PUN --msd-xlsx $MSD --outdir $OUT

# 5. post-processing
python collect_results.py --outdir $OUT
python postprocess.py --outdir $OUT --years 2023 2024
python core_width.py --outdir $OUT --years 2023 2024
```

On Windows PowerShell, set `$env:MILP_THREADS = "1"`, `$pun = "..\data\raw\20230101_20231231_PUN.xlsx", "..\data\raw\20240101_20241231_PUN.xlsx"` and `$msd = (Get-ChildItem ..\data\raw\EsitiMSD*Nord*.xls* | ForEach-Object FullName)`, and pass `$pun` and `$msd` in the same way. With `--game`, every solved day is appended to `game_ref_<year>_days.jsonl`, so an interrupted run restarts from the missing days. The whole-megawatt runs (`gran1`) reach the time limit of 300 s on most days, about 30 hours per composition and year.

All daily problems are solved to a relative gap of 0.01% within 300 s. The identical units of each class are merged into one unit of summed power and energy, which has the same value, since every constraint of a unit is homogeneous in its power and energy.

## Results

| File | Content |
|---|---|
| `scenarios.csv` | One row per scenario and year: standalone, aggregated and threshold-free values, value of aggregation and of admission, revenue by product and class, allocations and gains under the four rules, units below their standalone value, solver tolerance |
| `durations.csv` | Value of admission of a 0.5 MW unit for 1, 2 and 4 h under the reference and the price variants |
| `units_<scenario>_<year>.json` | Per-unit standalone and threshold-free values, allocations under the four rules, aggregated revenue and band by unit and product |
| `game_ref_<year>.json` | Annual value of every class composition of the game (EUR), days solved, tolerance, threshold-free value per unit |
| `game_ref_<year>_days.jsonl.gz` | Daily values of every composition (compressed; decompress to resume a run) |
| `post_ref.json` | Shapley value, nucleolus, core and single-unit core projections, largest excess of each rule, fixed-cost bounds, Monte Carlo replay |
| `core_width_small_<year>.json` | Core interval of one small unit in every composition, in kEUR |
| `comps_fcrdepth_<year>.json` | Class pools and their unions under the price-responsive FCR |
| `schedules_ref_<year>*.npz` | Hourly schedules and inputs of the reference runs, aggregated and standalone |
| `summary_*.csv`, `durations_*.csv` | Timestamped outputs of the runs, merged into the two CSV files above |

Money is in EUR in the JSON files written by `experiments.py` and in kEUR in the summaries, in `post_ref.json` and in the core-width files.
